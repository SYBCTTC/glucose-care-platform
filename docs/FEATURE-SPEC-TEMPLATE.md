# 功能需求模板（Feature Spec）

> 用途：后续所有功能开发都按本模板提需求。模板里每一项都对应本项目的一条硬约束，
> 填全后 AI 可直接实现，不用来回追问。
>
> 相关规范：`docs/ROADMAP.md`（阶段）、`docs/ERROR-CODES.md`（错误码）、
> `docs/PERMISSION-DESIGN.md`（权限）、`docs/UI-DESIGN-TOKENS.md`（视觉）、
> `.codebuddy/rules/*`（强制规则）。

## 使用方式

1. 复制下方「空模板」到对话或新建 `docs/specs/<模块>-<功能>.md`；
2. **必填项**（标 ⭐）不能留空，不确定就写"待确认"并列入第 11 节；
3. 提交需求时注明阶段号，例如：`P4-患者建档，按 FEATURE-SPEC-TEMPLATE 填写`。

## 填写约定

| 项 | 约定 |
|---|---|
| 权限点 | 只能用 `packages/shared/src/dict/roles.ts` 的 `PERMISSION.*`；需要新的先说明并加进字典 |
| 错误码 | 只能用 `docs/ERROR-CODES.md` 已有码；需要新的写明语义，由实现方登记码表 |
| 数据范围 | 从 `RESOURCE.*` 选（PATIENT/DEVICE/AUDIT），决定服务端如何过滤 |
| 字段命名 | 前后端统一小驼峰，时间用 ISO 字符串，金额/数值明确单位 |
| 迁移 | Prisma 迁移、鉴权、审计、CI/部署**禁止 AI 自行决定**（见 README 第四节） |

## 填写示例（患者建档，节选）

作为 **护士长**，我要 **为患者建档**，以便 **该患者可纳入统一管理**。

本次做：建档接口 + 表单页 + 列表脱敏展示。
不做：患者编辑、合并住院号、导入。

| 接口 | 权限点 | 数据范围 | 审计 |
|---|---|---|---|
| `POST /patients` | `patient:manage` | PATIENT | `PATIENT_CREATE` |

业务规则：
1. 住院号院内唯一，重复 → `40002 PATIENT_NO_DUPLICATE`
2. 姓名/身份证/电话写入 `*Cipher`（AES/SM4）与 `*Masked`（脱敏值）
3. 科室取操作人科室，禁止跨科室建档（走 `assertInScope`）
4. 设备管理员（`NONE` 档）访问 → `30006`

错误码：`10001` 字段级 / `40002` toast-refresh / `30002` toast / `30006` toast。

验收：`dr.chen` 建内分泌患者被拒 `30006`；列表不返回身份证明文；审计表出现 `PATIENT_CREATE`。

## AI 收到需求后的执行约定

1. 先核对必填项，缺项先问，不猜；
2. 按 `packages/shared` 契约 → 服务端（Controller/Service/数据权限/审计）→ 前端（页面/权限守卫/错误呈现）→ 测试 的顺序实现；
3. 改共享包后必须走 `.codebuddy/rules/shared-package.md` 三步；
4. 完成后回写 `docs/ROADMAP.md` 对应阶段进度。
