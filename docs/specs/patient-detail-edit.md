## 1. 需求原文与范围

> 作为用户，我希望可以修改患者的信息，方便我管理患者。
>
> 做：患者详情界面，上半部分的患者信息模块，右下角「更多操作」下拉，新增一个「编辑患者信息」功能。
> 不做：右下角更多操作里的出院/入院办理（保持现状不动）。
>
> 业务规则：
>
> 1. 右下角「更多操作」下拉，新增「编辑患者信息」功能；
> 2. 点击后弹窗展示，其逻辑和住院管理-患者管理-卡片/列表-更多操作里面的编辑患者信息一致，
>    弹框可直接复用，更新接口可复用，权限点可复用；
> 3. 出院患者详情不需要有此功能；
> 4. 新增一个修改：在患者信息展示页面，姓名 性别 年龄 入院时间..，在年龄和入院时间中间
>    加一个糖尿病类型，展示对应，和姓名一样字体加粗加大。

## 2. 数据模型 / 接口 / 权限变更

**全部为零**：

- `Patient.diabetesType` 已存在，`GET /patients/:id` 已下发（`PatientDetail.diabetesType`）；
- 更新接口复用 `PATCH /patients/:id`（`patient:update` + `assertInScope` 当前/目标科室双判权 +
  仅住院患者可编辑 40004 + `PATIENT_UPDATE` 审计含 changedFields，见 `patient-update.md`）；
- 权限点复用 `PERMISSION.PATIENT_UPDATE`（医生无此权限 → 菜单项不渲染）。

## 4. 业务规则

1. **编辑入口可见性**：`status = INPATIENT` 且持 `patient:update` → 菜单项渲染；
   出院患者（规则 3）或无权限 → 整项不渲染（与详情页下拉既有「无权限仅隐藏该项」口径一致，
   区别于列表页出院 Tab 的置灰+tooltip）。全部菜单项不可用时整个下拉不渲染（P2-6 裁定 6 不变）。
   服务端 40004 独立兜底，前端隐藏仅为体验。
2. **保存成功**：停留原地重拉详情（detailVersion+1，摘要区科室/医护/糖尿病类型等随之刷新）；
   不 bump `glucoseVersion` / `statusVersion`——`update()` 只写 Patient 表，血糖与住院记录数据未变。
   （重拉详情期间壳层进 loading、子树重挂载，各子 Tab 随之重拉一次——与办理出院/住院刷新
   同款的壳层既有行为，非本次引入。）
3. **糖尿病类型展示**：摘要区「年龄」与「入院时间」之间，取 `DIABETES_TYPE_LABELS[diabetesType]`，
   样式同姓名（`fontSizeLG` + `fontWeight 600`、只显示值不带 label 前缀）；null → 「-」（裁定 Q2）。
